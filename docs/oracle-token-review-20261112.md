# 不正な設計のテストのoracleトークンの見直し（2026-11-12）

[English](oracle-token-review-20261112.en.md) / [日本語](oracle-token-review-20261112.md)

不正な設計のテストの`:oracle:`から、`iverilog@13.0`と`verilator@5.052`のトークンを取り除きました。
この記録は、どのトークンをなぜ取り除いたかを示します。
1回目の見直しでは確認していないトークンが残りましたが、同じ日の[2回目の見直し](#second-pass)で確認しました。
テストのコードと期待結果は変えていません。

<a id="what-was-wrong"></a>

## 何が誤っていたか

不正な設計のテスト（`:should_fail_because:`）が`:oracle:`に固定リリースを書けるのは、
そのリリースが、テストの意図した理由で、指定した行で設計を拒否する場合だけです。
リリースが対応していない構文など、別の理由による拒否は数えません。
この規則は[README](../README.ja.md#where-the-expected-outputs-come-from)にあります。

2026-10-26のコミットは、ランナーが一致と報告した多くのテストに、まとめて`iverilog@13.0`を加えました。
不正な設計のテストの多くで、Icarus Verilog 13.0は知らない構文で失敗しているだけです。
そのエラーは指定した行に出るので、ランナーには区別できません。
152本のテストは、コメントで「Icarus Verilogのエラーは数えない」と述べながら、`:oracle:`にIcarus Verilogを書いていました。

このトークンは集計に影響します。
実行確認率は、不正な設計のテストの合格を、`:oracle:`に固定リリースがある場合だけ数えます。
誤ったトークンがあると、規則を診断していないリリースで要求を確認済みと数えてしまいます。

<a id="how-it-was-checked"></a>

## 確認の方法

- リポジトリのレビューで、`iverilog@13.0`を持つ不正な設計のテストのうち、トークンが誤っていそうな253本を挙げました。
  152本はコメントが「エラーは数えない」と述べ、76本はコメントが「リリースがその構文に対応していない」と述べ、25本には記述がありませんでした。
- 固定リリースを書いている不正な設計のテストを、すべてそのリリースで実行しました。
  Icarus Verilog 13.0で1,173本、Verilator 5.052で550本です。指定した行のメッセージを記録しました。
- メッセージだけで決められない場合は、同じ構文の合法な形を試しました。
  リリースが合法な形にも同じエラーを出すなら、そのエラーは規則を診断していません。
- トークンを取り除いた後、変更したテストをスイートのランナーで再実行しました。状態が変わったテストはありません。

## レビューした集合の外で見つけたトークン

`iverilog@13.0`を持つ残りの920本のうち、624本は指定した行のエラーが構文エラーです。
これらを調べ、合法な形を試して、5個のトークンが誤りだと確認しました。

- `ch18/test_illegal_packed_struct_member_rand`と`ch18/test_illegal_packed_union_member_rand`:
  アンパック構造体の`rand`メンバは合法ですが、同じ構文エラーになります。
- `ch33/test_illegal_config_positional_parameter`: 合法な`use #(.W(8))`も同じ構文エラーになります。
- `ch27/test_illegal_generate_module_block_extern_task`: インタフェースの中のextern taskは合法ですが、同じ構文エラーになります。
  このテストは`verilator@5.052`を残します。
- `ch6/test_ch6_extra_event_not_bit_storage`: 構文エラーではありません。Icarus Verilogは「変数が見つからない」と報告します。
  合法な`e = f`と`e = null`でも同じです。

`verilator@5.052`を持つ550本のうち、125本は指定した行のエラーが構文エラーで、3本は未対応を示すエラーです。
6個のトークンを取り除きました。

- `ch17/test_illegal_checker_in_class`、`ch17/test_illegal_checker_in_function`、
  `ch17/test_illegal_checker_module_instance`、`ch27/test_illegal_generate_checker_block_module_instance`:
  同じ場所に置いた合法なcheckerインスタンスも、同じ構文エラーになります。
- `ch6/test_ch6_extra_event_not_bit_storage`: イベントへの代入を未対応と報告します。合法な`e = f`と`e = null`でも同じです。
- `ch6/test_illegal_handle_to_real_cast`: キャストを未対応と報告します。このテストは`iverilog@13.0`を残します。

## 1回目の見直しで確認しなかったもの

この節の2項目は、[2回目の見直し](#second-pass)で確認しました。ここには、1回目の時点の内容を残しています。

- `iverilog@13.0`を持つ不正な設計のテストのうち、指定した行のエラーが構文エラーでないものが296本ありました。
  メッセージは記録しましたが、1本ずつ規則と照らし合わせてはいませんでした。
- 4個のトークンは疑わしいまま残しました。
  33章の3本（`test_illegal_config_default_use`、`test_illegal_config_design_after_rule`、`test_illegal_config_two_design_statements`）は
  configの文法の規則を扱いますが、Icarus Verilog 13.0はconfigを構文解析するだけで、その後は読み飛ばします。
  `ch35/test_35_rest_dpi_class_formal`はVerilator 5.052を書いています。
  規格が禁じている構文ですが、Verilatorのエラーは未対応という言い方です。

1回目の見直しの後、不正な設計のテストは1,975本でした。そのうち918本が`iverilog@13.0`、544本が`verilator@5.052`を書いていました。

## 2回目の見直し（2026-11-12）

2回目の見直しでは、1回目に残したトークンを確認しました。
10本のテストから、さらに11個のトークンを取り除きました。`iverilog@13.0`が8個、`verilator@5.052`が3個です。
テストのコードと期待結果は変えていません。

<a id="second-pass-what-was-checked"></a>

### 確認した範囲

`iverilog@13.0`を持つ不正な設計のテスト918本は、すべて確認しました。

- 指定した行のエラーが構文エラーでない299本。メッセージを、テストの行と合わせて1本ずつ読みました。
  このうち14本では、合法な形も実行しました。295個のトークンを残し、4個を取り除きました。
  1回目はこのようなテストを296本と数えましたが、今回の分類では299本です。
- 指定した行で構文エラーになる、手書きのテスト120本。それぞれ、同じ構文の合法な形と合わせて実行しました。
  116個のトークンを残し、4個を取り除きました。
- `tests/gen/ch22`の生成したキーワードのテスト496本すべて。どれも予約語を識別子に使い、構文エラーになります。
  識別子の名前を変えると、すべてコンパイルできます。496個のトークンはすべて残します。
- 1回目に疑わしいとした33章のconfigのテスト3本。トークンは正しいものでした。
  Icarus Verilog 13.0は、同じ文の合法な形を構文解析し、そのあと「sorry」のメッセージを出してconfigを読み飛ばします。
  構文エラーを報告するのは違法な形だけです。
  これは文法の規則で、`ch10/test_illegal_charge_strength_on_wire`と同じです。

Icarus Verilogの側には、確認していないものは残っていません。

`verilator@5.052`を持つ不正な設計のテスト544本のうち、指定した行で構文エラーになるものは1回目に確認しました。
2回目は、残りの423本を扱いました。

- 1回目に疑わしいとした`ch35/test_35_rest_dpi_class_formal`。トークンを取り除きました。
- エラーが構文エラーでも未対応の表示でもない422本。
  このうち18本では合法な形を実行し、16個のトークンを残し、2個を取り除きました。
  残りの404個のトークンは、メッセージの文面だけで判断しました。メッセージが規則を述べていれば、トークンを残しています。
  この404本では合法な形を実行していないので、Icarus Verilogの確認より弱い確認です。
