## Tests corrected after import

Corrected 3 tests.

Fixed `module holder (input int d);` of `tests/ch8/test_param_class_package_vs_module_instance_specializations.sv` to `input var int d`.

- For a ANSI-style port, `input` with the port kind (net/var) omitted is a net of the default net type (23.2.2.3).
- Net data types are restricted to types such as 4-state integral types; 2-state `int` is not permitted (6.7.1).
- The specification itself also writes `input var int` in the example of the input port of the 2 value type ( 23.2.2 ).

The verification team of p06 and p16 has also found the other 3 tests to be defective for the same reason. The accepted tests were then checked against the same criteria, and these 1 tests met them.

Removed 1 citation(s) to `:lrm:` from each of the following 2 files.

- `tests/ch37/test_vpi_interface_tf_decl_relations.sv`：25.7.4
- `tests/ch30/test_specify_pulse_trailing_edge_limits.sv`：30.7.3

Both clauses were cited only as background for the syntax; their requirements are not mapped (explanatory comments remain). Each cited clause needs at least 2 tests (`coverage_depth.py --check --minimum-tests 2`). There was no other test that cited this 2 section.

Observed behavior and expected output are unchanged in all 3 tests. After the fixes, both simulators were rerun and the ledger’s input hashes were updated.
