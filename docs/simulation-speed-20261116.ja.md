# kirimasim 0.1.0 と Icarus 14.0 devel：Mac・WSL2 の比較と対策

[English](simulation-speed-20261116.md) / [日本語](simulation-speed-20261116.ja.md)

2026-11-16 の比較・原因調査をまとめた入口です。同じ13本での時間比の幾何平均は **Mac 1.065、WSL2 1.193**（kirimasim/Icarus）でした。Macは約6.5%、WSL2の今回の記録は約19.3%長い値です。**WSL2は別のctest/UVM実行が重なった参考値**で、空いた状態の再測定を依頼しています。P1の合格閾値を新設せず、各負荷の内訳から改善候補を示します。

## 読み方と測定条件

- [Macの詳細と全サンプル](simulation-speed-mac-20261116.ja.md)：Apple M5 Max、18論理CPU、128 GiB、macOS 27.2.1、AppleClang 21.0.0。OSの索引作成・エディタの背景活動は記録済みです。
- [WSL2の詳細と受領検証](simulation-speed-wsl2-20261116.ja.md)：Ryzen 9 7950X、32論理CPU、110 GiB、Ubuntu 24.04.4 / WSL2、Clang 20.1.8。別ジョブの影響とばらつきを明記しています。
- [原因調査・試作パッチ・効果測定](simulation-speed-analysis-20261116.ja.md)：Macのprofilingと、正式版／試作／Icarusの同時計測を記録しています。

kirimasimは v0.1.0 `cfa2ccd75989c1ebb9ed63303271183377364cf0`、Icarusは作業開始時に取得した14.0 devel `1eba3690d8314d79927df8690a7d97642dd93ce0` に固定しました。既存12本と規格由来のX/Zベンチ1本、N、期待値、driver、adapterのhashは両環境で一致しています。全572実行の出力と終了状態を検査しました。

各toolでn=1のwarmup1回、n=1とNを各5回、直列・順序交替で実行しました。主指標Δは `median(T(N))−median(T(1))`、比は `Δkirimasim/ΔIcarus` です。1未満ならkirimasimの時間が短い値です。Icarusのコンパイルは別記、kirimasimの解析とelaborationは実行時間に含まれます。全実行時間・n=1・min/max/MADも各詳細に残しています。

CPU、OS、compilerの異なる環境内の比を並べています。両マシンの絶対速度をひとつの指標へ混ぜず、幾何平均も各ベンチ等重みの記述統計として扱います。起動時間の完全分離や、差の統計的有意性は主張しません。

## 原因と対策の優先順位

1. **広幅演算のword処理。** Macの広幅ベンチではシフト・選択・連結へのbit単位の書込みがworker観測の63.2%を占めました。64 bit単位の試作で、Δは6.598秒→1.829秒、型情報cacheも加えると1.724秒。X/Zを保ったまま約74%短縮し、同時計測のIcarusは2.012秒でした。
2. **不変な型情報を事前に求める。** VMが各命令で繰り返す先頭operandの型取得をcacheする試作で、ゲート約19%、メモリ約15%、NBA約17%、待機約8%の時間削減を確認しました。型cache単独の対照も記録しています。
3. **残るVM処理と静的trigger構築。** 試作後もgate/UDPはIcarusの約1.51倍、メモリは約1.21倍です。型・operand位置の事前decodeや待機情報の再利用を次の候補にします。この追加効果は未測定で、NBA順序・delta・iff・VPI/force・参照寿命を保つ検証が必要です。

試作は5ケースで各5回の性能比較を行い、全13本の期待出力、比較元がある6本の全カウンタ、既存wide/valsemテスト7件と追加122,184回の参照照合を通しました。simulator本体のmainへはまだ適用していません。正式採用前に全体local CI・sanitizer・型/境界/aliasの回帰・大規模SIRのメモリ/起動・WSL2の効果を確認します。詳細と採用候補の差分は[原因調査](simulation-speed-analysis-20261116.ja.md)にあります。
