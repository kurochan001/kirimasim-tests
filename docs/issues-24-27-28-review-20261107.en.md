# Issues #24, #27 and #28: decisions and test fixes (2026-11-07)

[English](issues-24-27-28-review-20261107.en.md) / [日本語](issues-24-27-28-review-20261107.md)

This review compares the text of IEEE 1800-2023 with the current tests, their expected outputs and the Nightly results at `67321079`. The baseline is `kirimasim-tests` `a7cb07c0`. The standard's text is not reproduced. The review is an AI review by Claude Opus 5.5, not independent human approval.

<a id="corrected-tests"></a>

## Corrected tests

- The 14 tests `gen/ch4/test_gen_sched_assign_wait_*` ([#28](https://github.com/kurochan001/kirimasim-tests/issues/28)): a continuous assignment changes `v` from x to 11 at time 0, and 4.7 leaves open whether a reader already waiting on `@(v)` wakes at 11. `generators/scheduling.py` now makes the reader wait again until `v` is 22. The expected outputs are unchanged.
- `ch23/test_23_extra_port_coercion` (#28): in 23.3.3.1, coercing an input is a permission and not a requirement. `x` is 1 with coercion and z without it, so the test accepts either and rejects 0 and x. `:fourstate:` is now `yes` because the test uses z.
- `ch17/test_checker_instantiation_connection_forms` (#28): the A.4.1.4 grammar has an empty actual, which slang rejects. Verilator 5.052 accepts it for the same checker placed outside the package. 17.3 compares the connections with module ports, but it also says output actuals are lvalues, and 16.8 asks for an actual for each formal with no default, so both readings have grounds. The test no longer uses empty connections and now also prints the parity of each instance.
- `ch37/test_vpi_program_interface_relations` (#28): the comment now records the conflict between 37.10 detail 3 and the 37.9 diagram. The expected output is unchanged.
