## 登録した主な観測

- NBAの旧右辺の保存、更新前の旧値、遅延／イベント待ち中も続く手続き実行、同じ更新時刻での予約順序。
- 予約後に添字を変える刺激による、NBAの代入先保存とブロッキング遅延代入の復帰時の代入先評価の違い。
- NBA更新で同じタイムステップ内のイベント待ちが再開すること。
- 手続きassignによる通常代入の上書き、deassign後の保持・入力非追従・通常代入の再開。
- 短パルスの慣性遅延による取り消し、net遅延とdriver遅延の合成、module出力からのnet遅延。
- 宣言初期化が継続ドライバではないこと、手続き開始時点での初期値、符号拡張・ゼロ拡張。
- 関数return／static cast／非defaultパターン項目の代入文脈。
- 配列連結の項目展開順、空の連結、文字列連結と配列連結の文脈差、型付き配列項目の展開。

net遅延の要求は、継続代入driverとmodule出力driverの2本を集合証拠にしました。
同じ実行回で両方が成功することを要求し、片方だけの成功では行全体を実行確認済みにしません。
集合証拠を持つ要求は累計13行です。

## M09：論理値だけでは駆動強度を検証できない

対象：[test_strength_ops.sv](../tests/ch10/test_strength_ops.sv)、
[test_strength_edge_cases.sv](../tests/ch10/test_strength_edge_cases.sv)。

それぞれstrong／weak／pullなどを指定しますが、各netは単独ドライバで、観測も論理0/1だけです。
例えばweakをstrongとして扱う誤実装でも、現在の出力は同じになります。
強度の異なるドライバを同じnetで競合させるか、強度そのものを観測する必要があります。
strength_opsのhighz0/strong1も1の入力しか観測せず、0を与えたときzになることは確認しません。
これらを強度の意味を検証する要求全体へは対応付けていません。

## M10：テスト名・表示と、実際に検査する代入動作の違い

[test_ct_assignment_complex.sv](../tests/ch10/test_ct_assignment_complex.sv) のT18は
`packed NBA` と表示しますが、実際の文は `nba_packed = 16'hBEEF` というブロッキング代入です。
NBAを検証するには `<=` を使い、更新前の値と更新後の値を別に観測する必要があります。
この指摘はT18についてであり、同じファイルにある他のNBAシナリオまで否定するものではありません。

[test_nba_complex_lhs_extended.sv](../tests/ch10/test_nba_complex_lhs_extended.sv) は
可変添字idxを使いますが、予約から更新までidxを変えません。
添字を更新時に評価する誤実装も同じ場所に書くため、合法なLHS形式の観測として登録し、
代入先の保存時点を確認したとは扱っていません。

また、[test_nba_part_select.sv](../tests/ch10/test_nba_part_select.sv) と
[test_nba_complex_lhs.sv](../tests/ch10/test_nba_complex_lhs.sv) の非重複スライスへの複数NBAは、
更新順を逆転しても同じ最終値になります。同じ宛先への順序保存は、重複する更新を持つ別テストで対応付けました。

## M11：明示deassign後の再接続は、assignによる暗黙の置換を実行しない

対象：[test_assign_deassign_2.sv](../tests/ch10/test_assign_deassign_2.sv)、
[test_assign_proc.sv](../tests/ch10/test_assign_proc.sv)。

どちらも新しいassignの前に明示的にdeassignします。
規格10.6.1の「assignが既存のassignを解除して置き換える」動作を検査するには、
古いassignが有効なまま新しいassignを行い、両方の右辺を変えて旧接続が切れたことを確認する必要があります。
明示deassign後の保持・通常代入の再開という有効な観測とは区別しています。

## M12：値や時刻を観測しないシナリオの扱い

[test_assign_edge_cases.sv](../tests/ch10/test_assign_edge_cases.sv) のTest7とTest10は、
入力やselectorを繰り返し変えた後に、出力値を読み取らず固定のPASSを表示します。
この2シナリオの伝搬を実装しなくても、同じ期待出力を生成できます。
各変更後の出力を直接検査する必要があります。

[test_continuous_assign_2.sv](../tests/ch10/test_continuous_assign_2.sv) のdelay1の検査は、
#0では旧値、#2では新値という観測だけです。正確な1単位の遅延までは確認できません。
別のrise/fall遅延テストの時刻付き遷移列を、伝搬遅延・短パルス取り消しの要求へ登録しました。

同様に、release後に#1を待ってからnetを読むテストを、即時復帰の完全な証拠にはしていません。
aliasの片側から駆動するテストだけでは双方向性を確認できず、
forceの有効期間中に右辺を変えないテストでは継続的な再評価を確認できないことも記録しました。
