## 照合と変更

- [#40](https://github.com/kurochan001/kirimasim-tests/issues/40)：指摘どおり。
  `ch14/test_syntax_clocking_drive_forms` の1ビット変数は、10.7の代入時の切り詰めにより
  2〜5を保持できなかった。`d` を3ビットへ広げ、サイクル遅延の各形式を異なる値で
  識別する目的と期待出力を保持した。Verilator 5.052 の両 seed で一致したが、
  新たな oracle トークンは追加していない。
- [#41](https://github.com/kurochan001/kirimasim-tests/issues/41)：指摘の旧コードは修正済み。
  `16939d7a` で、specparam を localparam に代入する形から generate 条件で使う形へ変更されている。
  6.20.5は parameter/localparam の初期値や宣言の範囲への使用を禁じるが、この条件式への使用は許す。
  現在の `ch11/test_A_extra_specparam_range` は変更せず、Icarus 13.0で出力 `2` を再確認した。
  最新 kirimasim と Verilator 5.052 はこの式を拒否するため、全ツールでの成功とは扱わない。
- [#42](https://github.com/kurochan001/kirimasim-tests/issues/42)：指摘どおり。
  14.16の将来時刻への clocking drive は Re-NBA で更新される。
  `ch14/test_clocking_default_skew` の時刻8・18の Active での期待値を更新前の値へ直し、
  同時刻の Postponed で `$strobe` が更新後の値を観測する行を加えた。最後の時間スロットを
  完了させるため終了を時刻19へ移した。既存の `test_clocking_future_drive_in_re_nba` とも整合する。
  Verilator 5.052 は両 seed で Active の時点から更新後の値を出すので、
  `verilator@5.052` の oracle を取り消し、規格による期待値を保持した。
- [#43](https://github.com/kurochan001/kirimasim-tests/issues/43)：指摘どおり。
  37.60の呼出し文自身の `vpiName` は文ラベルであり、ラベルがなければ NULL になる。
  `ch37/test_vpi_immediate_assertion_parts.c` は37.42の `vpiTask` 関係からタスクを辿って
  呼出し先名を取得するよう修正した。期待出力の `pass_t` / `fail_t` は維持する。
  固定版ツールは後述の機能制限で期待出力を生成できず、動的な一致確認は未完了である。
- [#44](https://github.com/kurochan001/kirimasim-tests/issues/44)：指摘どおり。
  4.10 Table 4-1と38.36.2が許す `cbReadWriteSynch` の Pre-NBA / Post-NBA の選択を
  一方に固定していた。`ch4/test_pli_phase_chain_after_nba_and_end_write` は、
  このコールバックでは呼出し回数だけを記録し、NBAで捕捉した値と最終値を
  `cbReadOnlySynch` で観測する形へ修正した。
  Pre-Active の書込み10、NBAによる捕捉10、Pre-Postponed の書込み30とHDLの反応31は維持する。
  修正後はどちらの合法な read-write 実行順でも同じ期待値になる。
  Icarus 13.0で一致し、既存の oracle を維持した。Post-NBA固有の観測ではなくなったため、
  `:lrm:` から4.4.3.4を外し、コールバック対応表の4.10を加えた。
