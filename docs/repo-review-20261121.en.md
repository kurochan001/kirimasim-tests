## With the next change of the runners

`tools/suite_results.py`, `tools/normalize_output.py` and each `tools/run_<simulator>.py` are part of the digest of that simulator's saved results. These fixes wait, with the four left by the review of 2026-11-12, for the next change of the runners.

- A test whose `:files:` names an `.svh` puts its whole directory in its input digest (19 tests). The inputs of `ch22/test_include_nested`, for example, are 228 files, and any change in ch22 makes it stale. Only the candidate paths of each `` `include `` name should be hashed.
- Icarus compiles and Verilator builds in the caller's directory, not in the temporary one; iverilog looks for a relative `` `include `` there first.
- With a space in the repository path, the patterns (`\S+`) that remove the `$finish` and severity-task lines do not match.
- The kirimasim runner does not pass `--single-unit` for `:compilation_unit: single`.
- Lines of spaces only are removed (the README says empty lines), and Icarus, Verilator, Lyra and Ghost also split lines at `\f` and `\v`.
- The FST runner: the `:fst_expected:` file is not in the input digest, and the version and reasons can hold machine paths (no test uses this runner yet).
- The Ghost, SymbiYosys, slang and FST runners lack the guard that keeps an error of one test the failure of that test alone.
- The Ghost runner builds only the DPI file of a test with both `:dpi_c:` and `:vpi_c:` (the `_vpi.c` of the two such tests is empty).

## Waiting for the owner

- The kirimasim regression check did not count a change from pass to unsupported. Decided on 2026-11-21: it counts now.
- The history files keep growing: `coverage/behavior-history.json` on main is 29.9 MB (about 1.9 MB a day), `behavior-history.json` on the results branch 30.9 MB, `coverage/interaction-summary.json` 51.3 MB and `coverage/test-matching.json` 45.6 MB. GitHub warns at 50 MiB and refuses a push of a file over 100 MiB; at the current rate the history on main reaches 100 MiB around the end of December (an estimate). The recommendation is to move or drop the run lists of old runs, split the large files, and check the sizes in Check.
- The history on the results branch has two pairs of records of one run (runs 44656954132 and 42477954992). The fix prevents new pairs only; the two stay.
- Ten files `coverage/interaction-results/cross25`–`cross29` hold paths of a local macOS temporary directory (not a home path or a name). Replacing them means rewriting the `coverage/interaction-qualification/*-prior-digests.json` records of their SHA-256.
- The Actions cache is over its 10 GB limit (111 entries), because each Nightly saves about 930 MB of ccache under a new key. The four Lyra shards fail without their cache, so an evicted Lyra cache can drop that night's Lyra.
- Check builds the reference simulators from tags and does not verify the commits the tags point to (they are right now).
- `generate.py --check` does not watch the hand-written C files that decide expectations (three in `tests/ch35`, one in `tests/ch28`).

## Checked and found sound

- Coverage: an illegal design counts through a fixed-release token only when the version string matches it; `check_groups` are AND within a group and OR across groups; the runner digests cover every file the runners read.
- No transform of `tools/metamorphic.py` was found to change the meaning of a test.
- Secrets: the public logs, artifacts and results branch of the Ghost job show no private name, path or diagnostic. Every action is pinned to a SHA that matches its tag.
