# 章間クロスの0セルの仕分け

[English](chapter-cross-triage.en.md) / [日本語](chapter-cross-triage.md)

この資料は`tools/chapter_cross_triage.py`が生成します。 [章間クロス検証マトリクス](chapter-cross-matrix.md)の非対角セルについて、 モデルの登録がない理由と次の確認先を整理しています。

- [仕分けマトリクスCSV](../coverage/chapter-cross-status.csv)：縦横41章。数字の代わりに下記の分類コードを表示します。
- [全章対の作業一覧CSV](../coverage/chapter-cross-triage.csv)：各章対の根拠、優先度、因子候補、期待する観測、確認済みテストと探索候補。
- [仕分け台帳](../coverage/chapter-cross-triage.json)：AIが刺激・観測と期待値を照合した記録、入力ハッシュ、追加設計の仮説。

<a id="current-account"></a>

## 現在の内訳

上下対称の重複を除いた820章対のうち、モデル登録済みは173対、0セルは647対です。 0セルを、既存検証あり3対、追加検証候補2対、対象外117対、後回し・要精査525対に整理しました。 既存検証の根拠には、重複を除く3テストを登録しています。

- `M`：有限モデルに章対を登録済み。登録数・合格数は元の数値マトリクスを参照。
- `E1`／`E2`／`E3`：相互作用を検査する既存テストを確認済み。章対として有限モデル表に未登録。末尾はモデル化を検討する優先度。
- `C1`／`C2`／`C3`：追加検証の設計案。共有状態や境界を特定した候補で、既存テストが存在しないとの断定ではありません。
- `N`：現在の計画で動作クロスの対象外。章の性質または本スイートの対象範囲を理由に指定。
- `R`：後回し・要精査。低リスクと確認したわけではなく、優先度も未評価。引用探索の候補から次回照合する余地があります。
- `D`：対角線。本表の仕分け対象外です。元の表では主題章のモデル数を表示します。

根拠のある対象外`N`と未精査の`R`を区別しています。 未確認のセルを対象外や低リスクとみなして隠さないためです。

<a id="next-to-consider"></a>

## 次に検討する順番

P1〜P3はこの検証計画内の優先度で、Issueの実装優先度とは独立です。 P1はイベント領域や参照・格納先の境界など、複数機能の規則が同じ観測に効く項目、 P2は他の型・階層・API境界、P3は基礎的な展開や拡張です。

登録済みのP1候補はすべて有限モデルへ移しました。P2/P3候補と未精査のRは残っており、全章対の検証完了を意味しません。


<a id="bases-and-limits-of-the-decision"></a>

## 判定の根拠と限界

台帳の確認者はCodex (GPT-6), AI review、確認日は2026-11-05です。 Eはソース中の刺激と観測、期待値を確認して登録します。入力ハッシュには期待値やC側の入力も含めます。 この資料はソースと期待値の照合記録・設計案です。実行の合否はクロス検証レポートで確認します。 分類コードや同時引用件数は、モデルの計画数・合格数・要求カバレッジに加算しません。

因子候補は次のモデル設計の案です。既存テストが挙げた全水準を検査済みという意味ではありません。

全正例シミュレーションの`:lrm:`を走査した同時引用件数と、最大3件の未レビュー探索候補も作業一覧に載せます。 同時引用は探索の手掛かりで、刺激・観測の照合をした件数ではありません。表示用の`$display`なども含み得ます。 同時引用0件でも、メタデータに第二の章が書かれていないテストが存在する可能性があります。 負例やformalはこの引用探索の対象外です。Eを章全体の網羅やt-way達成率には読み替えません。

Cはモデル化の仮説で、合法条件と規格の根拠、既存テストとの重複を照合してから実装します。 Eについても全件を因子モデル化する必要はなく、境界条件の回帰として維持する選択があります。

<a id="out-of-scope-policy"></a>

## 対象外の方針

- 第1章：概要は独立した動作要求を定めないため、動作クロスの軸としては対象外。
- 第2章：引用規格の一覧は独立した動作要求ではないため、動作クロスの軸としては対象外。
- 第34章：保護エンベロープは本スイートの動作検証の対象範囲外。対応方針が変わるときに再確認する。

これは本計画の範囲指定で、規格として検証不要との判断ではありません。 対象範囲が変わるときは台帳の方針も再確認します。

<a id="update-and-check"></a>

## 更新と検査

```sh
python3 tools/chapter_cross_matrix.py --update
python3 tools/chapter_cross_triage.py --update
python3 tools/chapter_cross_triage.py --check
python3 -m unittest discover -s tools -p test_chapter_cross_triage.py
```

Eへ昇格するには、両章の規則が同じ観測に効くことをソースと期待値で確認して、台帳に入力ハッシュを保存します。 既存の入力や期待値が変わった場合は検査が失敗します。照合せずにハッシュだけを更新しません。 Cには因子と水準の候補、観測したい違い、優先理由を残します。新しい有限モデルが章対をカバーしたときは、 該当するE/Cエントリを再確認して台帳から外します。履歴はgitに残ります。 Checkは仕分け台帳と生成物の整合性を確認します。シミュレータの実行・ビルドは行いません。
