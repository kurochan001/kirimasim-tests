The author of the table is Codex ( GPT-6 ), AI review, and the date of the confirmation is 2026-11-05. E registers the stimulus and the observation in the source and confirms the expected value. The input hash includes the expected value and the C-side input. This paper is a comparison record and design proposal of the source and the expected value. The classification code and the number of simultaneous citations are not added to the number of plans, number of pass, and required coverage of the model.

The number of simultaneous citations scanned in the `:lrm:` of the all-normal simulation and the number of unreviewed search candidates of up to 3 are also listed in the task list. The simultaneous citations are clues of the exploration, and not the number of cases in which stimulus and observation are compared. You can also include `$display` for display. In the 0 case, it is possible that there is a test that does not have a second chapter written in the metadata. Negative examples and formals are not included in this citation search. ## Update and check

```sh
python3 tools/chapter_cross_matrix.py --update
python3 tools/chapter_cross_triage.py --update
python3 tools/chapter_cross_triage.py --check
python3 -m unittest discover -s tools -p test_chapter_cross_triage.py
```

To upgrade to E, we verify that the rules in both chapters work for the same observation with the source and the expected value, and save the input hash to the log. If the existing input or expected values are changed, the check fails. Do not update only the hash without matching. In C, we leave candidate factors and levels, differences we want to observe, and reasons for prioritization. When a new finite model covers a chapter pair, review the corresponding E/C entries and remove them from the registry. The history will remain in git. Check checks the compatibility of the sorting table and the product. No run build of the simulator.
