## Comparison and changes

- [#45](https://github.com/kurochan001/kirimasim-tests/issues/45): the report is correct. In the 19.5.2 grammar, a comma inside the parentheses separates the values of a range list, so `(1 => 2, 3 => 4)` means `1 => {2, 3} => 4`, not two transitions. To keep the test's purpose, `ch19/test_cg_transition_syntax_all_forms` now uses `bins alt[] = (1 => 2), (3 => 4);`. The expected output is unchanged. The seven coverage steps were computed by hand from the stimulus and match: 42.86, 57.14, 71.43, 85.71, 85.71, 85.71 and 100.00.
- [#47](https://github.com/kurochan001/kirimasim-tests/issues/47): the report is correct. Of the three cases in which 8.16 lets `$cast` succeed, a variable holding null is neither an object nor the literal null, so the downcast fails. 8.26.5 refers to the same treatment, and `ch8/test_interface_class_null_handle_cast` expects the same reading. `ch8/test_dynamic_cast` now checks that the failing cast returns 0 and keeps the destination, and that the literal null succeeds and assigns null. Verilator 5.052 lets this downcast succeed, so its `verilator@5.052` oracle token was removed and the difference is listed in [simulator differences](simulator-differences.md).
