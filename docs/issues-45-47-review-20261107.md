## 照合と変更

- [#45](https://github.com/kurochan001/kirimasim-tests/issues/45)：指摘どおり。19.5.2 の文法では、括弧の中のカンマは範囲リストの値を区切る。したがって `(1 => 2, 3 => 4)` は `1 => {2, 3} => 4` であり、2つの遷移ではない。テストの目的を保つため、`ch19/test_cg_transition_syntax_all_forms` を `bins alt[] = (1 => 2), (3 => 4);` に直した。期待出力は変えていない。入力列から7段階のカバレッジを手で計算し、42.86、57.14、71.43、85.71、85.71、85.71、100.00 と一致することを確認した。
- [#47](https://github.com/kurochan001/kirimasim-tests/issues/47)：指摘どおり。8.16 が `$cast` の成功を認める3つの場合のうち、null を持つ変数は、オブジェクトを持つ場合にもリテラル null にも当たらないので、downcast は失敗する。8.26.5 も同じ扱いを参照し、`ch8/test_interface_class_null_handle_cast` は同じ読みを期待している。`ch8/test_dynamic_cast` は、失敗時の戻り値0と代入先の保持、リテラル null の成功と null の代入を確かめる形に直した。Verilator 5.052 はこの downcast を成功させるので、`verilator@5.052` の oracle を取り消し、[シミュレータの差分](simulator-differences.ja.md)に記録した。
