# 33章と40章：規格が決める範囲、ツールに任せる範囲、テストできる要求（2026-11-09）

[English](clauses-33-40-testability-20261109.en.md) / [日本語](clauses-33-40-testability-20261109.md)

[要求カバレッジ集計](behavior-coverage-summary.md) / [テストの書式](../README.ja.md#test-format)

外部レビューで、33章（設計の構成）と40章（コードカバレッジの制御とAPI）の要求カバレッジ（テスト設計）が低いと指摘されました（33章47.6%、40章64.1%）。
両章について、規格が決めている範囲とツールに任せている範囲を分け、このスイートの書式でテストできる要求を洗い出しました。
対応付けのなかった33章の33要求と40章の46要求を対象に、AI（Claude）が規格の本文と照らしました。人による独立した照合ではありません。

<a id="constraints-of-the-test-format"></a>

## テストの書式による制約

- テストは、まとめてコンパイルする1つ以上のSystemVerilogのファイルと、DPI・VPI用のCファイルです。ライブラリマップファイルを渡す欄や、ライブラリを選ぶオプションの欄はありません。
- マップファイルがなければ、すべてのセルはライブラリ`work`に入ります（33.3.1）。configで別のライブラリを名指すことはできますが、そのライブラリにはセルがありません。
- どの部分にカバレッジがあるかはツールに任されています（40.3.2.1）。そのため40章のテストは、どの適合した答えでも成り立つ関係を出力し、正確な値はOKが返ったあとに限って確かめます。
- いま比較しているシミュレータには、`$coverage_*`も40.5のVPIのカバレッジ属性も実装がありません。40章のテストの期待値は、当面は規格だけが根拠です。

## 33章：設計の構成

### 規格が決めている範囲

- 33.2、33.2.1：インスタンスとソース記述の結び付け、`library.cell[:config]`の記法。
- 33.3.1：マップファイルの文法、パスのワイルドカード、マップファイルからの相対パス、どのライブラリにも当たらないファイルの既定のライブラリ`work`。
- 33.3.1.1〜33.3.3：一致の優先順位、複数のライブラリに当たるファイルのエラー、同じ名前のセルの扱い、マップファイルのinclude、ソースファイルごとのセルの割り当て。
- 33.4〜33.4.3：configの構文と意味（design文、default・instance・cellの選択、liblistの順序と継承、空のliblist、use）、階層的なconfig、configからのパラメータの上書き。
- 33.5.4のうち、ソースと一緒に与えたdesign文のあるconfigが最上位のセルを決めること。
- 33.7：`%l`・`%L`とVPIの`vpiLibrary`・`vpiCell`・`vpiConfig`。

### ツールに任せている範囲

- マップファイルの名前と、ツールにそれを読ませる方法（33.3.1）。ファイルごとにライブラリを選ぶコマンドラインのオプション（33.3.1.1の注記）。
- 事前コンパイルするか、コンパイル済みのセルをどこにどう保存するかなどの使い方（33.5〜33.5.3）。33.5自身が説明のための節だと述べています。
- コマンドラインでのconfigやライブラリの探索順の指定（33.5.4の分割コンパイルの部分、33.8.1。`-L`は推奨にとどまります）。
- 実在する2つのライブラリを区別する動作は、すべてマップファイルを前提にしています。

### テストできる要求

- 既存のテストで観測している6要求を対応付けました（33.4.1の構文、33.4.1.1のdesign文が1つであること、33.4.3のパラメータのリセットと識別子の範囲と非リテラルのlocalparam、33.5.4のdesign文による最上位の選択）。
- 新しいテストを書いた対象：33.4.1.5（空のliblist、liblistの順序と継承）、33.4.1.6（useとliblistの両方の規則）、33.4.3（上書きに使える名前は、親のスコープでbind文が使える名前に限られること。合法な対照は、例4のどちらの読み方でも通る階層名にしました）。
- このほか、`33.4.1.6`を引用に足せば既存の`tests/ch33/test_illegal_config_default_use.sv`で観測できる要求が1つあります（残件）。

### この書式ではテストできない要求（21要求）

- マップファイルが要るもの：33.3.1の文法・相対パス・ワイルドカードの5要求、33.3.1.1の曖昧さのエラーと優先順位、33.3.2のincludeの2要求と内容の制限、33.3.3のセルの割り当て、33.6.1のconfigなしのライブラリの順序。
- ツールのインタフェースやコマンドラインの仕組みのもの：33.3.1のマップファイルを読む時期、33.8.1の`-L`。
- 使い方の説明で、出力が観測できないもの：33.5の事前コンパイルの扱い、33.5.1の2要求、33.5.2、33.5.3。

マップファイルを渡すランナーの欄（例えば`:libmap: @lib.map`）を設ければ、マップファイルが要る要求の多くは、33.8.2・33.8.3にならって`%l`の出力で確かめられるようになります。

## 40章：コードカバレッジの制御とAPI

### 規格が決めている範囲

- 40.2.1：すべての種類に共通のAPI、最低限の種類（文、トグル、FSMの状態と遷移、アサーション）、部分階層の問い合わせ。
- 40.2.2：種類ごとの数え方（1回実行された文、0と1の両方になったビット、到達したFSMの状態、成功したアサーション）と、インスタンスにわたる和。
- 40.3.1：`SV_COV_*`のマクロと値。
- 40.3.2.1〜40.3.2.5：制御の動作とその戻り値（表40-1）、定義かインスタンスか・モジュールか階層かの範囲（表40-2）、最大値と現在値、mergeとsaveの名前と状態。
- 40.4〜40.4.7：FSMの指示（状態ベクタ、部分選択とFSM名、連結、次の状態、同じ宣言の複数の信号、状態のパラメータ、2種類のコメント）と自動抽出に対する優先。
- 40.5.1〜40.5.3：VPIの定数、各ハンドルに対するカバレッジの属性、`vpi_control`の開始・停止・リセット・確認・保存・merge。

### ツールに任せている範囲

- 設計のどの部分にカバレッジがあり、どのオプションで有効になるか（40.3.2.1）。
- 文カバレッジの単位（文かブロックか）、トグルの部分的なカバレッジと回数、FSMの自動抽出、カバレッジのデータベースの形式（40.2.2、40.4、40.3.2.5）。
- レポートでの表示名（40.4.2のFSM名など）。
- 規格に定めのないもの：40.2.1が求めるFSMの遷移カバレッジに対応するAPIの定数（40.3.1にも40.5.1にもない）と、40.4.3に反する指示の結果。

### テストできる要求

- 既存のテストで観測している27要求を対応付けました（共通のAPIと最低限の種類、インスタンスにわたる和、制御の戻り値と範囲、最大値と現在値、mergeとsave、FSMの指示、VPIのカバレッジ制御）。
- 新しいテストを書いた対象：40.2.2のトグル・文・アサーションの定義、40.3.2.1の確認の組み合わせ、40.4.4・40.4.5の次の状態の指示、40.5.2・40.5.3のVPIの属性とsave・merge。実行回数（`vpiCoveredCount`）は、40.2.2が任意としているので確かめません。
- このほか、`40.4.1`を引用に足せば既存の`tests/ch40/test_coverage_fsm_pragma_states.sv`で観測できる要求が1つあります（残件）。

### この書式ではテストできない要求（3要求）

- 40.2.1のFSMの遷移カバレッジ：問い合わせるためのAPIの定数もVPIの属性もありません（規格の不足）。
- 40.3.2.5のデータベースの表現：規格が処理系定義としています。
- 40.4.3の連結の指示での選択の禁止：コメントの中の文についての制限で、違反したときの扱いが書かれていないので、診断を求められません。
