# SVA参照評価器とフォーマル検証

2026-10-26時点の実装・検証結果と、再実行の手順です。目的は、シミュレータが未対応のSVAについて、規格から決めた期待出力と、それを確かめる参照評価器の両方を検査することです。

## 参照評価とフォーマル検証の役割

Python製の[参照評価器](../tools/sva_reference/README.md)は、IEEE 1800-2023の16章と附属書Fをもとに、系列の一致、性質の成功・失敗・空成功・未確定と、その確定時点を計算します。固定されたテスト入力を評価して出力を生成し、その後で既存の期待出力と比較します。M2の10本、M3の28本、M4の7本の計45本が一致しています。M3で判明した期待出力・説明の誤り2件は、ユーザー承認後に修正しました。

Yosys＋SymbiYosysによるフォーマル検証は、参照評価器の意味論をさらに検査する仕組みです。評価器の実際の計算から生成した回路と、条文から別に書いたRTLモデルを比較します。入力は自由変数にし、特定のテスト刺激に限定する`assume`は置いていません。

従来の10本のformal-pilotは固定刺激のモデル検査でした。今回の拡張では、対象とする入力の全組合せについて同値性を検査します。証明対象は選択した意味論モデルであり、元のSVテスト全体やシミュレータ実装全体の正しさではありません。

## 検証対象と結果

40モデルに対する有界モデル検査（BMC）がすべて成功しました。内訳は次のとおりです。

- **系列22モデル。** Pythonの重み付き微分による系列評価を、完全な有限状態機械として出力します。別に書いたRTLは、入力履歴から区間の端点を調べるか、カウンタ・フラグを使って一致を数えます。空一致、連結、繰り返し、goto/nonconsecutive、and/or/intersect、first_match、throughout、withinを含みます。真偽だけでなく、各時点の一致数も比較します。
- **性質16モデル。** 1〜3サンプルの入力全組合せについて、実際の評価結果を表にし、独立したRTL式と比較します。implication/followed-by、空前件の位置合わせ、untilの4形、トレース末尾でのstrong/weakの違いを扱い、結果の状態と確定tickを検査します。
- **4値のサンプル値関数1モデル。** 2ビットの4値ベクトルの前回値・今回値、全256組で、`$sampled`・`$past`・`$rose`・`$fell`・`$stable`・`$changed`を検査します。x/zはビットごとの2ビット符号で表現します。
- **gating付き`$past`の1モデル。** 2ビットの2値入力と1ビットのgateからなる4サンプル、全4,096通りで、通常・gating付きの過去1回／2回を各時点で比較します。宣言の既定値は2ビットの1に固定しています。

系列22モデルについては、ABC PDRを使った`prove`モードでも、入力長に上限を置かない同値性証明が成功しました。これは上記40モデルのうち22モデルに追加した証明です。対象式の繰り返し回数や遅延範囲などのパラメータは、それぞれの検証モデルに固定されています。

さらに、first_matchの同時終了、withinの複数一致、gotoの到達、xから1への立上りの4件で、`cover`による到達性検査が成功しました。

意図的に誤ったモデルを5種類用意した負例検査では、すべてBMCで反例を検出しました。具体的には、同時終了の重複を潰す、withinの右端を除外する、空一致を1tick遅らせる、前件不一致のfollowed-byを空成功とする、gating付き履歴に今回の値を先に入れる、という誤りです。first_matchの誤りは、PDR側でも反例が出ることを別途確認しました。

主実行は計71ジョブで、期待どおりのPASSが66件、期待どおりのFAILが5件です。PDR側の追加負例1件は別記録です。これらのFAILは検査経路を確かめるための予定された結果で、現行の評価器で新たな誤りが見つかったという意味ではありません。UNKNOWN・TIMEOUT・ERRORは成功に数えません。

詳細な式・入力範囲・深度・版・ハッシュは、[技術報告](../tools/sva_reference/FORMAL_REVIEW.md)と[結果JSON](../tools/sva_reference/fixtures/formal_symbolic_results.json)にあります。[追加PDR負例](../tools/sva_reference/fixtures/formal_pdr_negative.json)と[反例VCDの索引](../tools/sva_reference/fixtures/formal_counterexamples/index.json)も保存しています。

## 証明範囲の読み方

系列のBMC深度は有限パターンが8ステップ、無限繰り返し等を含む5パターンが16ステップです。PDRによる系列の証明には、この深度による入力長の制限はありません。

有限入力の性質・関数モデルは、サンプル列全体を組合せ回路に展開して検査しています。結果JSONにあるSBY深度2はソルバーのステップ数であり、意味論上の入力が2サンプルだけという意味ではありません。各モデルの`semantic_ticks`がサンプル数です。これらは有限入力についての結果であり、一般の無限時間の性質を証明したものではありません。

系列・性質の入力は2値です。x/zを明示的に扱うのは、4値サンプル値関数のモデルです。複数クロック、イベント領域の一般的なスケジューリング、手続き内アサーションのキュー、任意の型・算術・ユーザー関数、VPIなどは、今回の証明範囲に含みません。

比較用RTLも、AIが規格から作成したモデルです。別実装との一致は追加の検証材料ですが、規格解釈の全例外や、あらゆるSVA式を網羅したという主張にはしません。Yosysは生成した検証回路を読み込みます。元の未対応SVA構文をそのまま処理する構成ではありません。

## 再実行

コマンドはリポジトリのルートで実行します。Python側のコードは標準ライブラリだけを使います。フォーマル検査を実行するには、SBY・Yosys・Yices・ABCを含むOSS CAD Suiteが必要です。今回の実行環境はOSS CAD Suite 20260816、Yosys 0.68+71、SBY 0.68、Yices 2.7.0、ABC 1.01です。

`SBY_BIN`にSuite内の`sby`実行ファイル、`FORMAL_RUN_DIR`に新規または空の出力ディレクトリを指定します。ツールのPATHは子プロセスにだけ設定し、通常のシミュレータ選択を変更しません。

```sh
python3 tools/sva_reference/formal.py --sby "$SBY_BIN" \
  --output-dir "$FORMAL_RUN_DIR"
```

このコマンドは、40件のBMC、22件のPDR証明、4件のcover、5件のBMC負例検査を実行します。生成RTL、SBY設定、ログ、反例・到達例のVCD、`results.json`が出力されます。既存の実行結果は上書きしません。追加PDR負例は、この既定の71ジョブには含まれません。

対象を絞る場合は`--case`を繰り返します。次の例では、対象に登録された証明・cover・負例検査も実行します。

```sh
python3 tools/sva_reference/formal.py --sby "$SBY_BIN" \
  --case first_match_tie --case gated_past --output-dir "$FORMAL_SMALL_DIR"
```

ツールを動かさずに、生成RTLだけを確認することもできます。`FORMAL_RTL_DIR`も新規または空のディレクトリを指定します。

```sh
python3 tools/sva_reference/formal.py --emit-only --output-dir "$FORMAL_RTL_DIR"
```

保存済み結果が現在のソースに対応し、必要なジョブが揃っているかの検査は次です。このコマンドはソルバーを再実行しません。

```sh
python3 tools/sva_reference/formal.py \
  --check-results tools/sva_reference/fixtures/formal_symbolic_results.json
```

`tools/sva_reference/`のPythonソースが変わると、保存済み結果のソースハッシュ検査は不一致になります。再実行した結果と差分を確認してから証跡を更新します。期待出力との不一致が出た場合は、モデル・入力・符号化・有限トレースの境界を調べ、条文で判断します。既存の期待出力や説明を修正する際は、承認と[台帳更新手順](../coverage/README.md)に従います。

## メタデータ・CI・網羅率との関係

`:oracle:`の値は変更していません。参照評価器との一致やフォーマル検査の成功は、シミュレータでの実行確認率には加算しません。専用のフォーマルCIジョブは追加しておらず、必須化の方針は別途決める事項です。

既存の単体テストには、生成処理・入力の自由度・負例・結果判定・証跡の鮮度などを確認する10件の回帰検査を追加しました。これらは外部フォーマルツールを実行しません。実装時点では、全193件の単体テストと既存の整合性検査が成功しています。
