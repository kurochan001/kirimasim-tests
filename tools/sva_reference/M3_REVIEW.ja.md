## 1 .前件のマッチがないfollowed-byの評価試行

テスト：`tests/ch16/test_property_implication_operator_forms.sv`。

ソースの4つの指令はモジュールレベルである。16.14.5に従い、それぞれ毎クロックtickで新しい評価試行を開始する。各フェーズで`go`がゼロとなる4つのtickも含まれる。`go ##1 a` は4つの開始点で一致しない。第16.12.7節と第16.12.9節は演算子を区別する。含意は、マッチがなければvacuousに成功する。followed-byはマッチを必要とするため、失敗する。このテストのfollowed-byの指令には、外側の`go |-> ...`ガードがない。

したがって、各followed-byの失敗カウンタには、4回の失敗に加え、`go`が高値のときに開始する試行が失敗すれば、その分も含まれる。第1フェーズは`#-# 4, #=# 5`、第2フェーズは`5, 4`、第3フェーズは`5, 5`となる。2つの含意数は変化しない。元の期待値では、各フェーズでgoが立っていない状態から開始した4回の失敗を、すべて数えていなかった。

ソースの説明は、`go ##1 a`の終了時点についても不正確である。`go`は第1の位相tick、`a`は第2の位相tickにあるため、前件は第2のtick、すなわち開始から1tick後に終了する。修正されたコメントは，そのアラインメントと4つの追加のスタートの両方を明示的にする。

生成した結果は次のとおりである。

```text
x at tick 1: |-> 0, |=> 1, #-# 4, #=# 5
x at tick 2: |-> 1, |=> 0, #-# 5, #=# 4
x at tick 0: |-> 1, |=> 1, #-# 5, #=# 5
```

対象を絞った単体回帰検査は、独立した5tickの入力語を使い、ガードなしの形式を明示的なガード付き形式と比較する。結果を選択するために，このテストの期待値を読み込まない。

<a id="2-empty-repetition-does-not-add-a-clock-tick"></a>

## 2 .空反復によってクロックtickは追加されない

テスト：`tests/ch16/test_zero_repetition_no_sample.sv`。

第16.9.2.1節は、現在のtickで`empty ##1 b`を`b`に簡約する。したがって、`start |-> (a[*0] ##1 b)`は、`start`が真となるtickで`b`を検査する。`(a[*0]) |=> b`では、16.12.7内の空の前件の場合も、この単一クロックのプロパティの現在のtickに後件を位置合わせする。`a[*0]`がサンプルを取らないこと（16.12.22）は、遅延を挿入しない。

時刻10では、サンプルした`start`が1、`b`が0なので、両アサーションは直ちに失敗します。時刻20では、両方とも1なので、新たな両試行は直ちに成功します。どちらのアサーションにも、時刻30のtickを待つ保留中の評価試行はない。25 時点での正確な数値は次のとおりである。

```text
zero: pass=1 fail=1; antecedent: pass=1 fail=1
```

当初の期待出力はゼロの失敗を示し，その説明は両チェックを次のチックまで遅延させた。承認された修正は、刺激とアサーション式を維持し、これらのカウント、説明／コード内のタイミングコメント、および引用条項を変更する。対象を絞った単体テストが、時刻10と20の2つのサンプリングtickで、両方の判定を直接検査する。
