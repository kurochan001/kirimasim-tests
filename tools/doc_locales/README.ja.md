# ドキュメントの翻訳データ

[English](README.md) / [資料一覧](../../docs/README.ja.md)

リポジトリのMarkdown文書は[`docs/languages.json`](../../docs/languages.json)で日英の対を管理します。
既存の日本語ファイル名は維持し、英語版を`.en.md`へ配置します。既存の英語ファイルには
`.ja.md`を対応させます。ルートのREADMEと履歴も後者の形式です。各資料から対応言語へ移動できます。
翻訳した見出しには元の見出しのアンカーを残し、既存の節リンクを維持します。

<a id="updating-handwritten-documents"></a>

## 手書き文書の更新

新しい資料は両言語のページを作り、`docs/languages.json`に`en`・`ja`・`source`・`source_language`・`generated`を持つ項目を追加します。正本とする資料と言語、ツールで生成するかどうかを指定してください。生成資料を追加する場合は、出力するツールも両言語の生成と検査に対応させます。

両言語を更新し、意味・コマンド・数値・対象範囲を合わせて確認します。その後、一覧と指紋を更新します。

```sh
python3 tools/documentation_languages.py --update
python3 tools/documentation_languages.py --record
python3 tools/documentation_languages.py --check
```

`--record`は両言語を更新した後の内容の識別値を記録する処理で、翻訳や意味の正しさの認定ではありません。
検査では、片言語の欠落、言語切替リンクの不足、未解決のプレースホルダ、Markdownの登録漏れ、
手書き文書の指紋変更を検出します。生成レポートは、各生成器でも出力の整合性を確認します。
READMEには現在の状態と実行方法を記載し、日付付きの変更・測定・過去の実行本数は履歴や個別記録へ置きます。

<a id="updating-generated-documents"></a>

## 生成文書の更新

既存のレポート生成器は、同じ元データから日英を生成します。
[`doc_localization.py`](../doc_localization.py)と`en.json`・`ja.json`を使い、
CIでオンライン翻訳、モデルの取得、推論は行いません。

JSON辞書は、技術情報を保護した原文の文と訳文を対応させます。コード、パス、リンク、数値、版、
状態の識別子、モデルIDはプレースホルダへ置き換え、元どおりに復元します。
プレースホルダの不足・不整合や翻訳の欠落は、原文のまま公開せずエラーにします。
リンクの表示名は別に翻訳し、文中のリンクは読んでいる言語の資料へ向けます。
言語を切り替えるリンクは、明示した言語への移動を維持します。

辞書の訳文はテンプレートです。同じ記号に異なる識別子・数値・演算子が入る場合があります。式と記号を保持し、原文に明示されていない値や比較の方向を推定して言葉に置き換えないでください。

原文を追加するときは対応する辞書へ訳文を登録し、文脈を含めてレビューします。
`ZXQPH<n>QXZ`はそれぞれ1回ずつ保持し、文法に必要な順序の変更だけを認めます。
生成器で更新し、両言語を確認してください。生成レポートの直接編集は行いません。
技術識別子、実行可能な例、生の実行証跡、ライセンス条文は原形を保ちます。

`coverage/`にある章間マトリクスの5種類のCSVにも、`.en.csv`の英語版を配置します。
見出し・章名・説明用の列を訳し、件数・分類や状態のコード・因子値・入力パス・生の期待出力・
実行の来歴は元の値を保持します。英語ガイドからは英語CSV、日本語ガイドからは元のCSVへ移動します。

Nightlyでは`behavior_coverage.py`と`interaction_coverage.py`に`--bilingual-export`と`--source-url`を渡し、
`main`の登録パス以外にも両言語を公開します。対応する文書の対の翻訳を再利用し、概要と詳細は出力先の
同言語の兄弟ファイルへ、リポジトリのガイドは出典コミットの同言語ページへリンクします。
`results_history.py`はREADME・要約・グラフの表示文を静的な日英の文言から生成します。
どちらの公開経路も、生の実行JSONと診断文を原形のまま保持します。

新しい説明文の辞書キーは、リポジトリのルートで次を実行して確認できます。例の文章を置き換えてください。
マーカーの番号は文ごとに振り直します。表示されたキーを使い、訳文でも各マーカーを1回ずつ保持します。

```python
import sys
sys.path.insert(0, "tools")
from doc_localization import protect, sentences

text = "Check all 27 cases with `a <= b`."
masked, literals = protect(text)
for key, original_ids in sentences(masked):
    print(key)
    print({f"ZXQPH{index}QXZ": literals[int(original[5:-3])]
           for index, original in enumerate(original_ids)})
```

<a id="translation-provenance-and-limits"></a>

## 翻訳の来歴と限界

FAQ、用語集、Nightlyガイド、クロス検証方法のガイド、入口の整理、有限55モデルの観測目的は、この変更で直接翻訳・確認しました。
残る資料の一括翻訳の草稿には、ローカルで実行した
[MADLAD-400-3B-MT](https://huggingface.co/google/madlad400-3b-mt)の
`fa184c675da0b5c9e1c8694fccd4e12e2d422094`を使いました。
モデルカードのライセンス表記はApache-2.0です。翻訳ソフトウェアと重みは、このリポジトリの実行時依存には含めません。

手書き資料の翻訳は、原文と照らしてAIが文脈を確認しました。生成資料についても、数値・リテラルの対応、否定、スケジューリング、観測範囲、専門用語を重点的に確認しました。

原文が途中で切れている場合は、続きを推定せず欠落を明示します。この注記によって、元の要求台帳やテストのメタデータを修復・変更することはありません。

翻訳の存在と構造の検査は、すべての技術的な記述の解釈が無誤りであることを保証しません。
否定、規格上の要求、スケジューリング、証明範囲、計画上の網羅と実行確認の違いは、文脈を含めて確認します。
AIによる翻訳・確認は人による承認ではありません。翻訳の誤りを見つけた場合は、
引用条項と元の実行証跡を保持して両言語を修正してください。
